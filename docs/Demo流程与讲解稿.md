# Demo 流程与讲解稿（约 5 分钟，可直接录视频）

对应评审五项：创意 / 技术难度 / **完成度（权重高）** / 社会价值 / 合规。每个环节标注了它在证明哪一项。

## 0. 一句话定位（开场 20 秒）

> 我们做的不是"AI 生成图检测器"，而是售后客服的**证据鉴真 Agent**：把图片、订单、物流、账号、跨工单、聊天等多源证据做交叉验证，给出"可信 / 存疑 / 高风险"三级结论、可执行的处置建议和话术，由客服做最终判断。
> 判断原则：**P 图 ≠ 造假**，关键看编辑痕迹是否落在诉求相关的部位。

## 1. 演示前准备（5 分钟）

| 步骤 | 命令 / 动作 |
| --- | --- |
| 后端（Mock 模式，无需 Key） | 在 `backend/` 下：`python -m uvicorn app.main:app --port 8000` |
| 前端 | 在 `frontend/` 下：`npm run dev`，浏览器打开 `http://localhost:5173` |
| 自检 | 右上角显示"Mock 模式"；点"评估"页签能看到三张结果表；`python -m pytest -q`（在 `backend/`）全部通过 |
| 录屏 | 浏览器缩放 100%，隐藏书签栏，全程不切页面 |

**诚实说明（讲解和答辩都要说）**：演示工单的图片是占位图，对应的视觉描述与取证结果来自回放数据（面板里会标"回放"）。真实模型的能力只在"评估"页用公开数据集上的真实图片评测，并明确标注了局限。不要把回放结果说成真实模型的效果。

## 2. 演示顺序与台词

### 2.1 开场与界面（0:20–0:40）
- **操作**：停在工单列表，指一下左侧 10 个工单、中间订单/物流/账号/聊天卡片、右侧"Agent 核验"。
- **台词**：左边是待处理的仅退款工单，中间是客服平时要翻的订单、物流、账号、聊天记录，右边是 Agent。客服不需要在多个系统之间切换。

### 2.2 T1001：P 图 ≠ 造假（0:40–1:30）【证明：创意、合规】
- **操作**：选 T1001，点"开始核验"，等步骤流跑完。
- **看点**：
  - 结论：`存疑 · 信息不足`，处置：要求补证。
  - 备注区有"人脸有编辑痕迹（如美颜），与诉求部位无关，不计入风险"。
  - 建议话术是礼貌地要求"近距离拍摄泵头损坏的具体位置"。
- **台词**：这位买家用了美颜，但他诉求的是泵头损坏。我们检测到了编辑痕迹，却**没有**因此判他造假，因为痕迹在人脸，和诉求部位无关。真正的问题是：图里看不到泵头的损坏，所以系统没有拒绝，而是生成一句话术让客服去要定向补拍。

### 2.3 T1002：多源交叉的高风险（1:30–2:20）【证明：技术难度】
- **操作**：选 T1002，核验，悬停证据条目，图片上会出现对应区域的框。
- **看点**：结论 `高风险`；证据包括整图疑似 AI 生成（0.91）、物理合理性存疑（液体边缘过于平滑、高光方向与瓶身不一致）、签收前就拍了照、晚报。
- **台词**：单看"像 AI"我们不会下结论。这里是图像证据、物理一致性、时间线（签收前拍照、晚报）几类**独立信号**互相印证，才给出高风险。处置也不是直接拒绝，而是"退回验货再审"。

### 2.4 T1003：跨工单素材复用（2:20–2:45）【证明：技术难度、社会价值】
- **操作**：选 T1003，核验。
- **看点**：`S9_exact_dup`，凭证图与其他账号的工单 H0001 几乎相同（距离 2）。
- **台词**：黄牛常把同一张图反复用在不同账号上。我们用感知哈希做跨工单比对，这类信号不依赖 AI 检测，对压缩也稳健。

### 2.5 T1006 / T1009：该放行就放行（2:45–3:30）【证明：社会价值、防误伤】
- **操作**：依次选 T1006、T1009，核验。
- **看点**：两个都是 `可信`，处置"直接处理"。T1006 有物流记录"转运中心：外包装破损，已加固"；T1009 同批次近 14 天已有 4 起可信的同类投诉。
- **台词**：图里有疑点，但**物流轨迹和同批次投诉**能解释它。我们优先控制误报：宁可补证，也不冤枉真实消费者。

### 2.6 T1008：边界与合规（3:30–3:45）【证明：合规】
- **操作**：选 T1008（过敏投诉）。
- **看点**：`健康类 · 转专人`，没有任何防骗逻辑。
- **台词**：涉及健康安全的诉求，系统不做真假判断，直接转专人，这是伦理边界。

### 2.7 评估页：数据与局限（3:45–4:40）【证明：完成度、技术诚实度】
- **操作**：点"评估"页签，依次指三张表和顶部的黄色局限框。
- **要点（数字来自 `data/eval`）**：
  - VLM 能描述破损：真实破损图 14/15 报出破损，真实完好图仅 3/24 误报破损，但它**分不出** AI 假图。
  - Community Forensics：原图口径 AUC 0.98，经缩放 + JPEG 压缩后降到 0.66，12 张假图 0 张检出，47 张真图 0 误报。
  - TruFor 局部篡改：未压缩的拼接图 AUC 0.98，**JPEG q95 就掉到 0.52**；因为真图在 0.55/0.80 阈值下有误报，我们把模型分数低于 0.90 的一律记 0。
- **台词**：我们没有回避局限。像素取证在压缩后基本失效，所以它在系统里只是"高置信才加权"的弱证据。主力是交叉验证和举证流程。这也是我们的取舍：误报优先，识别不了就让客服补证，而不是乱判。

### 2.8 收尾（4:40–5:00）
- **台词**：总结一下：①多源交叉，不是单点检测；②痕迹 × 诉求相关性，P 图不等于造假；③按可信度分级处置，给出话术并支持补证闭环；④数据说话，局限透明。

## 3. 评委 Q&A（预案）

| 问题 | 回答要点 |
| --- | --- |
| 检测器在压缩后基本失效，价值在哪？ | 这正是设计依据：像素取证只作弱证据；主力是订单/物流/跨工单/账号/话术的一致性，这些信号不受压缩影响。评估页公开了压缩消融。 |
| 是 AI 判官吗？ | 不是。工具定位是辅助决策：给证据链、风险等级、处置建议，客服做最终判断。LLM 只描述和生成话术，**裁决由确定性规则完成**。 |
| 演示数据是真的吗？ | 演示工单是自建场景，图片是占位图，结果来自回放（面板标"回放"）。真实模型只在评估页用公开数据集的真实图片评测，并标明了样本量与局限。 |
| 误报怎么控制？ | 阈值按真图校准：TruFor 模型分数低于 0.90 记 0（原阈值会误报约 11%）；未检出异常不当作"真"；证据不足时走补证而不是拒绝。 |
| 美颜/修图的用户会被冤枉吗？ | 不会。编辑痕迹要和诉求部位叠加才计风险，否则只作备注（T1001）。 |
| 怎么防止用户反过来用 AI 绕过？ | 单一图像信号不决定结论；跨工单复用、物流时间线、账号行为、补拍要求构成多重约束，补拍要求还能增加造假成本。 |
| 数据与合规？ | 评测图片来自公开的 Amazon 美妆评论数据集的买家实拍图；假图是我们用生图模型自造的，仅用于离线评测；TruFor 权重仅限非商业/研究用途，已在代码和文档中标注；模型接入不绑定厂商。 |
| 落地需要什么？ | 对接真实工单、订单、物流接口与图片原始上传文件（未重压缩的原图能显著提升取证能力）；阈值用真实数据重新校准。 |

## 4. 录制与应急

- **录制顺序**严格按第 2 节，T1001 到 T1002 之间不要重复点击"重新核验"。
- **断网**：Mock 模式不依赖网络，可完整演示；不要现场切换到真实 LLM。
- **口径统一**：任何地方都不要说"检出率 XX%"而不带"压缩后"或样本量。引用数字以评估页为准。
- **PPT 配图建议**：①T1001 的备注区截图（P 图 ≠ 造假）；②T1002 的证据链截图；③评估页压缩消融表。
