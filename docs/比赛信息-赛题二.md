### 赛题 2 信任守护师 —— 创造者的 AI 卫士
> "你还相信你看到的吗？"

**赛题主题**：打造一款懂美妆内容生态的"AI 鉴真专家"，帮忙识别种草文章、评论区与 AI 生成素材中被篡改、拼接或伪造的文案与图片，守护创作者与消费者之间那份看得见、信得过的真实。

**任务细则**：
1. 开发多模态检测方案，识别所选场景中的合成/篡改/伪造痕迹，并给出可解释的判定依据；
2. 构建 Agent，结合风险预警与处理建议，通过数据集展示从识别到决策的完整闭环。

**最终产出**：内容核验 Agent —— 判断内容真伪、标出可疑之处并说明判定依据，核验过程清晰。

## 三、赛题主理人深度解析（最重要）【直播】破赛秘籍

> 以下为赛题二主理人在"破赛秘籍"直播中的完整讲解要点，按原意整理。

### 3.1 出题背景：AI 让造假门槛越来越低
- 内容创作中的 AI 成分越来越多，创作门槛越来越低。
- 目标：用 AI 做**内容校验**，把**带有负面意图**的内容识别出来，帮助消费者、品牌和整个生态了解什么才是真正可信的内容。
- **注意措辞**：主理人强调针对的是"带有不好的或负面意图的内容"，**AI 创作本身没有好坏**。

### 3.2 两个真实痛点案例
1. **GEO（Generative Engine Optimization，生成式引擎优化）—— 今年 315 曝光的话题**
   - 市面上很多被大模型采纳的回答，背后可能来自**伪造的专家、伪造的证书、伪造的内容**，最终被大模型当作答案输出给用户。
2. **恶意消费者 / 黄牛用 AI 伪造图片骗退款**
   - 伪造**包装破损、漏液**等图片申请客诉，获取退款。
   - 有了 AI 技术，这类负面内容的制作变得越来越容易。
   - 目标：既要继续赢得真实消费者的青睐，又要**降低运营端的压力**。

### 3.3 工具定位（关键）
> "这个工具**并不是帮我们去筛选哪些正确、哪些是错误的**，而是帮助我们，不管是**消费者端**还是**运营客服端**，去**减少风险、提高识别能力**。"

即：**辅助决策工具**，不是自动判官。

### 3.4 欧莱雅内部的真实使用场景：客服端
客服会接触两类内容：
1. **工单场景**：消费者客诉时提出诉求，并提供**图片、证据**，甚至提供**医保/医药费证明**说明自己确实因产品患病，以此申请退款或退货。
2. **社交渠道场景**：消费者在**抖音、小红书**等社交平台发布的内容，欧莱雅会把这些内容收集回来，希望**尽快识别哪些是真正需要跟进的**。

AI 的位置：**降低识别过程中的风险，提高识别速度**，从而更高效地服务真实消费者。

### 3.5 核心判断原则：P 图 ≠ 造假
> "造假或者说 P 图本身不是重要的，而是 **P 图是不是用来做造假**，是不是用来完成一些不那么正规的目的。这个才是我们需要去发现的内容。"

主理人举的例子：
- 消费者用 AI **修了个脸**，但旁边拍的**包装本身确实是破损的**，他只是想申诉包装破损 → 这个 AI 痕迹**不影响申诉**，不应判为风险。
- 消费者声称包装破损，但**破损部位本身**被识别出 AI 生成痕迹 —— 例如**高光、光影、条纹、材质**不符合真实状态，或算法直接识别出图片中的 **AI 指纹** → 应快速定位为风险。

**结论**：判定必须**结合诉求意图**，看篡改区域是否与诉求相关（篡改区域 × 诉求主张 的关联判断）。

### 3.6 交叉识别能力（加分方向）
主理人特意补充了"赛题原文没写"的内容：
- **账号特征**：黄牛/恶意消费者往往以某类**固定账号或某种形式特征**出现。
- **交叉素材**：同一套素材在不同工单/账号间重复使用。
- **上下文冲突**：前后说法矛盾、图文不一致、与订单信息冲突。
- 这些**交叉信号**都会影响"内容是否可信"的判断。

### 3.7 今年与去年的区别
> "去年更多是想看你在某一方面能不能把（大模型）用起来；今年更希望看到**更完善的思考**。因为目标是做**可信**，本身目的并不是识别出这件事情**是 AI 还是不是 AI**，而是需要思考**什么样的情况下是可信的**。可能通过**交叉验证**、**设计一些举证方式**去做。"

→ **评委期待的不是"AI 生成检测器"，而是"可信度判定体系"。**

### 3.8 三个内容方向（任选 1–2 个或全覆盖）
1. **图文**
2. **视频**
3. **内容冲突**

> "这三个是我们觉得内容主要会出现造假或信任风险的方向。可以结合 1 到 2 个点集中做，或者全部覆盖。"

### 3.9 素材与数据
- 需要自己设计方案中的场景与素材。
- 可以**从公开网站或公开数据集**获取内容来做设计和风险提示。
- 官方原文要求"**通过数据集展示**闭环" → 需要自建/整理评测数据集。【待确认：官方是否提供样例数据】

### 3.10 期望的交付形态
> "对于客服场景，我们希望有一个**可视的看板**，告诉他这个地方出现了（问题）。"

- 例如在看板上标出"此处出现 AI 伪造痕迹"，由**客服结合诉求做最终判断**。
- 帮助客服在**人工定位问题**的过程中**更快**解决问题。

### 3.11 模型
- 主理人提到"希望结合阿里的模型"，但**已确认不强制**使用阿里云 / 千问，模型与技术栈自由选择。

### 4.2 欧莱雅客服的真实工作约束【直播】三心服务
（赛题二主理人的场景就是客服端，这些约束直接决定产品设计）
- **响应时效**：天猫要求 **30 秒**内响应，抖音要求 **15 秒**内响应；客服是**一对多同时接待**。
- **咨询量波动**：双十一大促咨询量可达日常的 **15 倍**。
- **舆情风险**：任何一次有瑕疵的服务都可能在社交媒体迅速放大。
- **"朋友心"原则**：售后场景中，要**像朋友一样相信和信任消费者**反馈的问题，先安抚再解决。
  → **对赛题二的启示**：系统**不能默认怀疑消费者**，误判真实消费者为骗子的代价极高（伤害品牌信任）。必须**低误报**、**分级处理**、**人工兜底**。
- **"求实心"原则**：售后处理前要看完**完整聊天记录、所有工单记录、整体订单情况与历史退款情况**，综合判断后给出最合理方案。
  → **对赛题二的启示**：可信度判断应融合**订单、历史退款、聊天记录**等上下文，而不只看单张图。
- **售后链路**：涉及平台、仓库、物流、工单系统等多个环节；欧莱雅已建售后中台，工单系统关联 14 个职能板块。
- **现有实时质检看板的不足**（主理人原话，虽针对赛题一但同属客服体系）：基于关键词、语义识别不充分；无法判定问题是否最终解决；没有整合订单、退款、投诉信息。

### 4.3 欧莱雅如何看待"信任"与"准确"【直播】先锋科技圆桌
- **线下门店是验证线上内容的最终防线**：消费者看了海量种草和测评，最终要来线下闻香、试色验证。
- 欧莱雅所有门店素材经过**品牌审批 + 合规审核**后远程推送，确保展示内容真实。
- 门店 AI 试装、肌肤检测基于**科学算法的客观结果**，"而不是简单给你开个美颜"。
- **准确率标准**：抖音原生客服模型准确率 80%，欧莱雅认为 20% 的错误量不可接受；与火山引擎用美妆知识图谱 + 海量问答微调后升至 **99%**，可独立解决 40% 在线问答。
  → **"大模型不是开箱即用，必须加上行业知识"**。
- **品牌知识大脑**：欧莱雅打通研发、电商、售后等部门，把成分、功效、品牌话术、肌肤问题整理为**权威、结构化**的品牌知识库，并自动同步给通义千问、豆包、蚂蚁阿福等平台，**"彻底告别 AI 胡说八道"**。
  → **对赛题二的启示**：功效宣称/成分真伪核验可以借鉴"权威知识库比对"的思路（如对照备案成分表、官方功效宣称）。

## 五、技术路线参考（阿里云官方）【直播】技术充电

> **已确认：不强制使用阿里云 / 千问 / 百炼 / QCA**，本节的具体平台方案**仅供参考，可不采用**。
> 仍然有效、与平台无关的部分：5.1（评委如何区分模型应用与 Agent）、5.4（选型原则）。

### 5.1 评委眼中"模型应用"与"Agent"的区别
> "如果项目只是把用户的问题发送给模型，再展示模型回答，那这就更像一个**模型应用**。如果它真的**访问了数据、调用了工具，并完成了一个端到端的任务**，才更接近 **Agent**。"

**Agent = 大模型 + 知识/记忆 + 工具 + 执行循环**

判断是否需要 Agent 的标准：是否需要**调用工具**、是否需要**分多个步骤**完成、是否需要**自动规划和执行**。

### 5.2 阿里云三条路线

| 路线 | 定位 | 适合 |
| --- | --- | --- |
| **百炼**（MaaS 平台） | 模型服务化 + 知识库 + 智能体 + 工作流，上手快、试错成本低 | 实时问答、秒级响应、面向用户的交互 |
| **QCA**（Coder Cloud Agent） | 全托管云端 Agent 运行平台；Agent / Environment / Session 三对象；支持文件输入、多智能体协作（协调者 + 子专家）、事件流可观测、产物（报告/CSV/HTML）交付 | 长任务、批量文件处理、无人值守、过程可追踪 |
| **高代码**（AgentScope + Coder + AgentCore） | 完全控制权，深度定制协作机制 | 专家之间需直接通信、多层递归委派、自定义协作算法 |

### 5.3 阿里云对赛题二的建议路线（仅参考，不采用也可）
> "如果是**信任守护者**，可以使用**百炼多模态模型完成图文识别**，再由 **QCA 协调检索、鉴伪和功效核验等专家任务**。只有协作算法本身需要高度定制时，才建议进一步考虑 AgentScope 方案。"

### 5.4 选型原则
- **先从最小闭环开始**，再逐步增加工具，"配置项越多不代表 Agent 越好"。
- **流程固定的部分用工作流**（更确定、易测试、可复现）；**需要灵活判断的部分用智能体**。
  - 主理人原话：固定的**售后分类、表单审核、内容处理链路更适合工作流**。
- **不要把所有工具都塞进同一个方案**，先选一条最贴合赛题的主路线，把端到端体验做完整。
- "方案的价值在于解决了什么问题，而不是技术栈有多复杂。"
- "选择在有限的赛程中**最有可能完成闭环**的工具。"

### 5.5 其他技术参考【直播】美遇AI
- **Harness**：一套约束、规范和规则体系，让模型在可控范围内执行任务（编排框架、工具链调用关系、记忆提取）。
- **多智能体协作**：单个 Agent 解决不了复杂业务（如售后），需多 Agent 串联编排。
- 落地三要素：**提示词规范**、**工作流（明确 SOP）**、**复杂任务智能体（判断 → 拆解 → 工具调用 → 知识提取 → 推理）**。

## 八、需求理解：官方原文 vs 主理人讲解

两份材料侧重点不同，方案需同时覆盖：

| 维度 | 官方原文 | 主理人讲解 |
| --- | --- | --- |
| 内容来源 | 种草文章、评论区、AI 生成素材 | 客服工单（客诉图片、医药费证明）、社交渠道（抖音/小红书） |
| 服务对象 | 创作者与消费者 | 消费者端 + **运营客服端**（重点） |
| 造假形态 | 篡改、拼接、伪造的文案与图片 | AI 伪造破损/漏液图、伪造专家/证书（GEO）、伪造证明 |
| 判定目标 | 判断内容真伪 | **判断在什么情况下可信**，篡改是否服务于欺诈 |
| 模态 | 文案 + 图片 | 图文 + 视频 + 内容冲突 |
| 交付 | 内容核验 Agent，标出可疑处并说明依据 | 客服可视化看板 |

**共同的硬核心**：
1. 多模态检测 + **可解释、可定位**的证据
2. Agent 编排 + 风险预警 + 处理建议
3. 用**数据集**展示**识别 → 决策**的完整闭环
4. 核验过程清晰可见

**候选场景**（待团队决策）：
- **场景 A：售后客诉鉴真**（主理人重点场景）—— 消费者提交破损/漏液/过敏图片 + 文字诉求 + 订单信息 → 判断证据是否可信、篡改是否与诉求相关 → 给客服风险等级与处理建议。
- **场景 B：种草内容鉴真**（官方原文点名）—— 种草笔记、评论区、AI 生成的使用前后对比图、伪造检测报告/专家背书 → 判断内容可信度 → 给平台/品牌/消费者提示。
- **场景 C：GEO 伪造信源核验** —— 伪造专家、伪造证书被大模型引用 → 溯源与交叉验证。
- 也可以以一个场景为主，其他场景作为扩展展示"可迁移性"。
