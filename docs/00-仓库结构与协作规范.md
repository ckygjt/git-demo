# 仓库结构与协作规范

## 一、目录约定

```text
git-demo/
├── README.md                      仓库总览：场景索引 + 快速开始 + 边界声明
├── .env.example                   环境变量示例（.env 本身被忽略）
├── .gitignore                     已排除 .env / .venv / data/images / 大文件
├── docs/                          文档，按场景分目录（入口 docs/README.md）
│   ├── 00-仓库结构与协作规范.md    本文
│   ├── scene-a-ecommerce/
│   └── scene-b-geo-forensics/
├── backend/                       场景A（历史路径，暂不重命名以减少迁移成本）
├── data/seed/                     场景A 种子数据
├── scripts/                       场景A 辅助脚本
├── scenarios/                     新场景统一父目录
│   └── scene-b-geo-forensics/     场景B：backend/ + web/ + data/
└── archive/v0-truthguard/         v0 旧项目归档，只读
```

### 为什么 `backend/` 不在 `scenarios/` 下

`backend/` 是场景A 的历史路径，重命名的收益（整洁）小于成本（队友本地路径失效、PR 冲突、历史追溯断裂）。因此约定：

- **存量不动**：`backend/`、`data/seed/`、`scripts/`、`docs/*.md` 保持原位
- **增量规范**：所有新场景一律放 `scenarios/<scene-name>/`，自带 `backend/`、`web/`、`data/`
- 未来若做统一迁移，单开一次 `refactor` PR 集中处理

## 二、新场景脚手架约定

```text
scenarios/<scene-name>/
├── README.md            场景说明、启动方式、示例数据
├── requirements.txt     该场景独立依赖
├── backend/app/         编排、工具、裁决、接口
├── backend/config/      阈值与规则外置（yaml）
├── web/                 前端（无构建工具，原生 HTML/CSS/JS）
└── data/                种子数据、上传件、案例落盘
```

每个场景的后端遵循同一套骨架（与场景A 同构，便于跨场景维护）：

1. `orchestrator.py` —— 以生成器逐步产出步骤事件，最后产出结果对象
2. `tools/` —— 外部能力统一为工具适配器，含 mock 与 real 两套实现
3. `fusion/` —— 证据交叉验证、规则裁决、处置建议
4. `config/` —— 阈值、权重、规则外置为 yaml，改配置不改代码
5. `main.py` —— FastAPI 接口 + SSE 流式步骤事件

## 三、分支与 PR

| 分支 | 用途 |
| --- | --- |
| `main` | 保护分支，只接受 PR 合并 |
| `feat/<scope>` | 新功能，如 `feat/geo-forensics-agent` |
| `fix/<scope>` | 缺陷修复 |
| `docs/<scope>` | 纯文档 |
| `refactor/<scope>` | 结构调整（需提前在 PR 说明影响面） |

PR 要求：

- 标题写明场景，如 `feat(scene-b): 新增药监局备案核验工具`
- 描述里说明：改了什么、是否影响场景A、是否需要新环境变量、如何验证
- 涉及路径移动或依赖变更的 PR，必须在描述中给出队友的迁移步骤

## 四、提交约定

```
<type>(<scope>): <subject>

type: feat | fix | docs | refactor | test | chore
scope: scene-a | scene-b | docs | repo | ci
```

示例：

```
feat(scene-b): 实现 S3 信源并行核验与降级
fix(scene-a): 修复杂乱 EXIF 时 exif 解析抛错
docs(scene-b): 补充 GEO 工作流设计与案例走查
```

## 五、安全基线

- `.env` 绝不入库；新增变量同步更新 `.env.example`（只写键名与说明，不写值）
- 日志与 SSE 事件禁止输出 Key、Authorization 头、完整请求体
- 示例数据一律虚构品牌/机构/专家/证件编号，避免指向真实主体
- 图片、模型、PPT 等大文件不入库

## 六、术语规范

| 用 | 不用 |
| --- | --- |
| 信源伪造风险 | 造假 / 诈骗（定性过重） |
| 证据链 | 线索 |
| 置信度 | 准确率 |
| 存疑 / 证据不足 | 无法判断（过模糊） |

结论文案必须带边界提示：本结论为风险研判，不作司法终局定论。
