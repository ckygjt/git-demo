# 场景 A 需求分析：售后客诉证据鉴真

> 版本：v0.1（2026-10-06）｜ 视角：产品经理
> 依据：`docs/比赛信息-赛题二.md`（官方赛题原文 + 赛题二主理人讲解 + 三心服务等直播）
> 标注约定：**【原话】**= 直播/官方明确说过；**【推断】**= 基于原话的合理推演；**【假设】**= 我们自定的，需验证或可调整

---

## 0. 一句话定义

**给电商售后客服用的"证据核验助手"**：消费者提交售后申请（文字诉求 + 图片证据）后，Agent 自动结合订单与历史信息，判断**这份证据能不能支撑这个诉求**，标出可疑之处、说明依据，并给出**下一步怎么处理、怎么跟消费者说**的建议。最终决定权在客服。

> 核心问题不是"这张图是不是 AI 做的"，而是 **"这份证据，能不能信到足以支持这次退款"**。【原话：主理人"目的不是识别是 AI 还是不是 AI，而是什么情况下是可信的"】

---

## 1. 背景：为什么要做

### 1.1 业务现状【原话】
- 欧莱雅客服在工单中接收消费者的客诉：诉求 + **图片证据**，甚至附**医药费/医保证明**，申请退款、退货。
- 黄牛和恶意消费者用 AI **伪造包装破损、漏液图片**骗退款；AI 让这类伪造越来越容易。
- 客服的时效压力：天猫 30 秒、抖音 15 秒内响应，一对多接待；大促咨询量约为平时 15 倍。
- 服务原则"朋友心"：售后场景要**先相信消费者**；"求实心"：处理前要看完整聊天、工单、订单与历史退款记录。

### 1.2 核心矛盾【推断】

```
       防骗退（品牌损失、运营压力）
                 ⇅  矛盾
       不误伤（真实消费者体验、舆情风险）
                 ＋
       没时间细看（15~30 秒时效、一对多）
```

客服今天只能二选一：**要么快速放行（被薅）**，**要么怀疑卡单（误伤 + 投诉 + 舆情）**。
人眼也越来越难分辨 AI 生成的破损图。

### 1.3 我们要解决的问题【推断】
让客服在**不增加处理时长**的前提下，**对可疑证据有据可依，对正常证据放心放行**。

## 2. 用户与角色

| 角色 | 在场景中的位置 | 核心诉求 | 优先级 |
| --- | --- | --- | --- |
| **一线售后客服** | 主要使用者，处理工单 | 秒级知道"这单能不能直接过"；有疑点时知道疑点在哪、该怎么跟消费者说 | ★★★ 主用户 |
| **二线复核 / 风控专员** | 处理被升级的高风险单 | 拿到完整证据包，快速做最终裁定；看到跨工单的团伙/重复模式 | ★★ |
| **客服主管 / 运营** | 管理者 | 看整体风险分布、骗退趋势、拦截与误判情况 | ★ （演示加分项） |
| **真实消费者** | 被核验对象（不直接使用系统） | **不被冤枉、不被反复刁难**，问题快速解决 | 约束条件 |
| **恶意申请者 / 黄牛** | 对抗方 | 以最低成本骗到退款 | 对抗对象 |

> 关键设计约束：**消费者看不到"风险评分"**；系统对消费者只体现为"客服请你补充一个视角/一段视频"这类低打扰动作。【推断，来自朋友心原则 + 主理人"设计举证方式"】

## 3. 现状流程与痛点

### 3.1 当前流程【推断，基于直播描述的电商售后通用流程】

```
消费者在天猫/抖音申请售后 ──▶ 填写原因 + 上传图片
        │
        ▼
工单进入客服工作台 ──▶ 客服人工看图 + 翻聊天/订单记录
        │
        ▼
客服判断 ──┬──▶ 同意退款/补发
           ├──▶ 要求补充证据（凭经验，话术不统一）
           ├──▶ 升级主管
           └──▶ 拒绝（风险：投诉、平台介入、舆情）
```

### 3.2 痛点清单

| # | 痛点 | 后果 | 来源 |
| --- | --- | --- | --- |
| P1 | AI 伪造的破损/漏液图肉眼越来越难辨 | 被骗退款，损失 + 运营压力 | 【原话】 |
| P2 | 时效紧，没时间细看图、翻全部历史 | 只能凭感觉放行或卡单 | 【原话】时效要求 |
| P3 | 无法区分"无害编辑"和"欺诈篡改"（美颜、滤镜、加标注 vs 伪造破损） | 误判：好人被怀疑 | 【原话】主理人修脸例子 |
| P4 | 单看一张图，看不到跨工单信号（同图多次使用、同账号高频退款） | 团伙/惯犯难识别 | 【原话】主理人交叉识别 |
| P5 | 怀疑时缺少标准的"补证"手段，只能硬拒或放行 | 拒绝引发投诉，放行被薅 | 【推断】主理人"设计举证方式" |
| P6 | 疑点无法清楚说明 | 二线复核要重看一遍；无法向消费者/平台解释 | 【推断】赛题"可解释判定依据" |

## 4. 用户需求（JTBD）

**一线客服**：
- **J1**：当我打开一个售后工单时，我想**一眼看到这单的可信程度**，以便正常的单秒放行。
- **J2**：当证据有疑点时，我想**看到疑点在图上的哪里、为什么可疑**，以便我自己也能确认，而不是盲信 AI。
- **J3**：当我拿不准时，我想**得到一个低冲突的下一步动作和现成话术**（比如请对方补拍某个角度），以便既不冤枉好人，也不轻易放过骗子。
- **J4**：当图上有编辑痕迹但与诉求无关时（如美颜自拍），我希望**系统不要报警**，以免我被误导。

**二线复核**：
- **J5**：当高风险单被升级给我时，我想**拿到一份完整证据包**（疑点、依据、关联工单），以便快速裁定。
- **J6**：我想**看到跨工单的关联**（同一张图、同一账号/地址的多次申请），以便识别惯犯。

## 5. 风险类型地图（我们要识别什么）

> 美妆售后场景下，"证据不可信"的具体形态。【推断 + 部分原话】

### 5.1 图像层面

| 类型 | 典型表现 | 判断线索 | 来源 |
| --- | --- | --- | --- |
| **R1 AI 生成破损/漏液** | 整图或局部由生成模型产生 | 高光/光影/材质/条纹不符合物理规律；AI 指纹；文字/Logo 畸变 | 【原话】主理人 |
| **R2 局部篡改** | 在真实产品图上 P 出裂痕、漏液、污渍 | 篡改区域定位；噪声/压缩不一致；边缘伪影 | 【原话】赛题"篡改" |
| **R3 拼接/挪用** | 网图、别人的晒单图、其他品牌产品图 | 反向检索/图库比对；与历史工单图片相似 | 【原话】赛题"拼接"；【推断】网图盗用 |
| **R4 重复使用** | 同一张图用于多个订单/账号 | 跨工单图片指纹比对 | 【原话】主理人"交叉素材" |
| **R5 皮肤问题图造假** | 过敏、烂脸图是网图或 AI 生成 | 同 R1/R3；与时间线是否吻合 | 【推断】主理人提到"得病" |
| **R6 单据/证明伪造** | 医院诊断书、医药费单据被 P | 文字区域篡改、字体/排版不一致、关键字段矛盾 | 【原话】主理人提到医药费证明 |

### 5.2 一致性层面（"内容冲突"）

| 类型 | 典型表现 | 判断线索 | 来源 |
| --- | --- | --- | --- |
| **C1 图与订单不符** | 订单是 A 产品/规格，图里是 B | 识别图中品牌/品名/规格，与订单 SKU 比对 | 【推断】 |
| **C2 图与诉求不符** | 说"漏液"，图上看不到漏液；说"瓶身破裂"，图里是盖子问题 | 诉求要素抽取 vs 图像内容 | 【原话】"上下文冲突" |
| **C3 时间线矛盾** | 签收很久后才报"收到即破损"；图片拍摄时间早于签收 | 物流签收时间、EXIF、申请时间 | 【推断】 |
| **C4 前后说法矛盾** | 聊天里先说 X，申请时改说 Y | 聊天记录 vs 售后原因 | 【原话】"上下文冲突" |

### 5.3 行为层面

| 类型 | 典型表现 | 来源 |
| --- | --- | --- |
| **B1 高频退款账号** | 同一账号短期多次"破损"退款 | 【原话】主理人"账号特征" |
| **B2 关联账号** | 多账号共用收货地址/设备，提交相似素材 | 【原话】"交叉的账号" |
| **B3 模板化话术** | 不同账号诉求文案高度雷同 | 【推断】 |

### 5.4 必须"放行"的情况（防误伤，与上面同等重要）

| 类型 | 例子 | 为什么不算风险 |
| --- | --- | --- |
| **N1 与诉求无关的编辑** | 人物美颜、修脸，但破损的包装是真的 | 【原话】主理人明确举例 |
| **N2 正常处理** | 裁剪、旋转、加箭头/圈注、压缩、截图转发 | 消费者正常操作 |
| **N3 拍摄质量差** | 模糊、暗光、反光 | 质量差 ≠ 造假，应建议补拍而不是判风险 |

> **核心判定原则**【原话推出】：
> **风险 = 可疑痕迹 × 与诉求的相关性**。
> 篡改区域落在"诉求所主张的那个部位"（如裂痕、漏液处）→ 高风险；落在无关区域 → 不计或仅提示。

## 6. 目标效果

### 6.1 对用户的效果（用户故事验收）

| 场景 | 系统应有的表现 |
| --- | --- |
| 真实破损图 + 附带一张美颜自拍 | **低风险，建议直接处理**；可附注"人物图有美颜，与诉求无关" |
| AI 生成的漏液图 | **高风险**；热力图圈出漏液区域；依据："液体反光方向与光源不一致""瓶身文字畸变"；建议**补拍视频**并给出话术 |
| 与 3 天前另一单完全相同的图片 | **高风险**；直接关联出历史工单作为证据 |
| 图片产品与订单 SKU 不符 | **中风险**；指出"订单为 X 50ml，图中为 Y"；建议核对 |
| 照片模糊看不清 | **不判风险**；建议请消费者补拍清晰照片 |
| 高频退款账号 + 轻微可疑图 | **风险上调**；展示账号历史作为依据 |

### 6.2 处置动作设计（风险等级 → 动作）

| 等级 | 含义 | 建议动作 | 对消费者的体感 |
| --- | --- | --- | --- |
| **低** | 证据可信 | 快速处理（退款/补发） | 秒过，无感 |
| **中** | 存疑但不足以下结论 | **动态补证**：按疑点生成具体要求（"请拍一段 5 秒视频，转动瓶身展示破损处，并露出快递单"） | 多一步，但合理 |
| **高** | 多条强证据指向造假 | 升级二线复核，附**证据包**；暂缓处理 | 客服礼貌告知"正在核实" |

**硬约束**：
- **系统永不自动拒绝**，拒绝只能由人做出。【推断：朋友心 + 主理人"由客服判断"】
- 每一条风险结论**必须附依据**；没有依据的分数不展示。【原话：赛题"可解释的判定依据"】

> "动态补证"是本方案的关键差异点：主理人说要"**设计举证方式**"，而 AI 生成单张静态图容易，**按要求实时补拍指定角度的视频**很难伪造。这把"判断真假"转化为"让造假成本变高"。【推断】

### 6.3 可量化目标【假设：比赛演示用，需在自建数据集上验证】

| 指标 | 含义 | 目标（初定） |
| --- | --- | --- |
| **误报率**（真实证据被判中/高风险） | 衡量"不误伤" | **≤ 10%**（最重要） |
| 高风险召回（造假证据被判中/高风险） | 衡量"防得住" | ≥ 80% |
| 依据覆盖率 | 中/高风险结论附带可定位依据的比例 | 100% |
| 单工单核验时长 | 从提交到出结果 | ≤ 30 秒（可在工单进入队列时异步完成） |
| 单工单成本 | 模型调用费用 | 在演示中展示，越低越好（主理人提到的加分思路） |

> 为什么误报率比召回更重要：一次误伤真实消费者可能引发投诉和舆情（三心服务的"舆情风险"）；漏掉的骗退还有中风险补证、二线复核两道防线兜底。

## 8. Agent 的职责边界【推断：对齐赛题"构建 Agent"与评委对 Agent 的定义】

Agent 需要**真正做多步决策和工具调用**，而不是"一张图丢给模型出个分"。典型执行过程：

```
1. 读工单 → 理解诉求（问题类型、部位、诉求）
2. 规划核验步骤（依诉求决定要查什么：漏液→查液体区域；错发→查 SKU）
3. 调用工具：
   - 图像取证工具（AI 生成检测 / 篡改定位）
   - 图像内容理解（识别产品、破损位置）
   - 订单与历史查询
   - 相似图检索（跨工单）
4. 交叉验证：把可疑区域与诉求部位对齐；比对订单、时间线
5. 证据不足时：生成补证要求，而不是硬下结论
6. 汇总：风险等级 + 依据链 + 建议动作 + 话术
```

## 10. 演示数据集需求【假设】

需要一个**带标注**的模拟工单数据集，用来展示"识别 → 决策"的闭环和量化指标。

| 类别 | 内容 | 获取方式 | 初定数量 |
| --- | --- | --- | --- |
| 真实-正常 | 真实产品破损/漏液照片 | 自己拍（用旧瓶子制造真实破损） | 30+ |
| 真实-无害编辑（N1/N2） | 同上 + 美颜、裁剪、标注 | 对真实图做无害处理 | 15+ |
| AI 生成（R1） | 生成的破损/漏液图 | 图像生成模型 | 30+ |
| 局部篡改（R2） | 在真实完好产品图上 P 出破损 | AI 局部重绘 / 手工 P 图 | 20+ |
| 挪用/重复（R3/R4） | 网图、重复提交 | 公开图 + 构造重复工单 | 10+ |
| 内容冲突（C1~C4） | 图与订单/诉求/时间线不符 | 构造订单与诉求 | 15+ |
| 单据伪造（R6，Should） | P 过的医药费单据 | 自制模板 | 10 |

每条样本配：诉求文本、订单信息（SKU、签收时间）、历史售后记录、**标注真值**（真/假 + 风险类型 + 应有动作）。

## 11. 风险与开放问题

| # | 问题 | 影响 | 应对思路 |
| --- | --- | --- | --- |
| Q1 | AI 生成检测器在压缩、截图、二次转发图上准确率会下降 | 单靠检测器不可靠 | **多信号交叉** + **动态补证**兜底；这也是主理人强调"交叉验证"的原因 |
| Q2 | 自建数据集分布可能与真实骗退图不一致 | 指标偏乐观 | 数据集中加入多种生成模型、多种压缩处理；如实说明局限 |
| Q3 | 订单、账号历史等数据只能模拟 | 交叉信号演示说服力 | 设计贴近真实电商字段的模拟数据，说明可对接真实系统 |
| Q4 | 补证视频的核验难度较高 | Could 项可能来不及 | 初赛先做"生成补证要求 + 话术"，视频核验放决赛 |
| Q5 | 是否需要覆盖视频证据（主理人的三个方向之一） | 范围 | 初赛聚焦**图文 + 内容冲突**，视频作为扩展 |

## 12. 与比赛评分的对应

| 评分维度 | 本方案的得分点 |
| --- | --- |
| 创意 | "风险 = 痕迹 × 诉求相关性"的判定原则；**动态补证**把鉴别真假变成提高造假成本 |

| 合规 | 永不自动拒绝、隐私脱敏、数据来源合规 |
